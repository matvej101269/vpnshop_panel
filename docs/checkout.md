# Страница оплаты

Новые заказы в RUB (тарифы и пакеты трафика) открывают `/pay/<случайный токен>` на `public_base_url`. Нужен публичный HTTPS-адрес панели. Сумма, скидка и параметры тарифа сохраняются до выбора метода. Счёт Lava.top создаётся при нажатии СБП (`PAY2ME/SBP`) или карты РФ (`SMART_GLOCAL/CARD`). Значение `lava_payment_provider` для этих заказов не используется. Другие валюты продолжают работать через прежние прямые ссылки; конвертация валют пока не добавлена.

Новая таблица `checkouts` создаётся сервисом `vpnshop-init` при обновлении. Ручная миграция не нужна. Старые платёжные ссылки продолжают обрабатываться прежним способом.

Один заказ создаёт не более одного успешного счёта. После выбора метода повторное открытие продолжает тот же счёт; смены метода после его создания пока нет. Создание защищено атомарным переходом состояния между веб-процессами. При определённом отказе API (400/422/429) можно выбрать метод заново. При тайм-ауте или неоднозначной ошибке повторное создание запрещается: администратор должен проверить историю Lava.top, прежде чем предлагать новый заказ. Если процесс завершился в момент запроса, заказ останется в `creating` и также требует проверки.

Для новых заказов успешный webhook должен содержать ожидаемую сумму и валюту. Обновление статуса и постановка на выдачу происходят одной транзакцией. Повторный webhook не добавляет вторую задачу. Невыбранный заказ действует 24 часа; существующее удаление старых pending payments ограничивает доступность более старых ссылок.

Проверка после обновления: создать новый рублёвый заказ в боте, открыть «Оплатить», проверить СБП и карту РФ на отдельных заказах. Проверить подтверждённую оплату, выдачу услуги и повторное открытие уже оплаченного заказа. Доступность методов и ограничения сумм определяет Lava.top; тесты API используют подмену ответов и не выполняют реальных платежей.

Локальные проверки: `python -m unittest discover -s tests -v`.
