# Страница оплаты

Новые заказы (тарифы и пакеты трафика) открывают `/pay/<случайный токен>` на `public_base_url`. Нужен публичный HTTPS-адрес панели. Сумма, скидка и параметры тарифа сохраняются до выбора метода. Значение `lava_payment_provider` для этих заказов не используется.

Поддерживаются все три валюты API Lava.top: RUB, USD, EUR. RUB: СБП, карта РФ (Smart Glocal или PAY2ME). USD: карта, PayPal, Apple Pay, PIX. EUR: те же методы плюс SEPA, iDEAL, Bizum, MB WAY, Bancontact. Матрица основана на схеме и примерах `https://gate.lava.top/docs/documentation.yaml` от 28.09.2026. Спецификация непоследовательна: enum указывает UNLIMINT, а некоторые примеры — UNLIMIT; код использует enum UNLIMINT. Некоторые региональные методы присутствуют только в примерах. Их фактическую доступность для аккаунта и ограничения суммы требуется проверять на Lava.top, она не гарантируется интерфейсом. CHECKOUT_PAGE закомментирован в документации и не используется.

Валюта выбирается в Telegram и хранится в `user_currencies`. Конструктор меню поддерживает действие «Выбрать валюту оплаты». Каталог показывает только включённые и видимые тарифы выбранной валюты. В `plan_periods` хранятся варианты 1/3/6 месяцев (30/90/180 дней) с отдельными целыми ценами. Заказ сохраняет выбранную цену, дни и скидку; изменения тарифа после создания заказа не меняют его условия. Ручное подключение в панели также требует выбора периода.

На сайте валюта зафиксирована заказом, конвертации нет. Клиент выбирает только поддерживаемый способ. Подмена валюты в URL не меняет заказ; котировка другой валюты или суммы отвергается сервером. Ограничения Lava.top проверяются до отправки запроса: минимум 50 RUB / 5 USD / 5 EUR, максимум 1 000 000 RUB / 10 000 USD / 10 000 EUR для динамической цены. Цена автоматически до минимума не увеличивается.

При обновлении текущие тарифы получают один период с прежними днями и ценой. Необычные сроки (например, 45 дней) сохраняются как редактируемый «Сохранённый срок». Автоматического объединения старых тарифов и назначения новых цен нет. Существующие подписки и история не меняются; старые кнопки покупки переводят на выбор периода. Варианты 3/6 месяцев включаются в панели явно.

Таблицы `checkouts`, `checkout_quotes`, `payment_attempts` создаются сервисом `vpnshop-init`. Ручная миграция не нужна. Заказы прежней версии, где invoice_id уже внешний, сохраняют свой канонический ID; при смене способа старый счёт регистрируется как попытка.

Смена метода создаёт новую попытку того же заказа. Для другой валюты создаётся новый заказ через бот. Ранее созданный счёт с теми же методом, валютой и суммой повторно используется. Старые ссылки не считаются отменёнными: API отмены разового счёта не документирован. Первый подтверждённый платёж ставит одну задачу выдачи по каноническому ID заказа; повторный webhook не дублирует задачу. Оплата другого счёта уже оплаченного заказа сохраняется как `extra_paid` и показывается в разделе «Система и логи» для ручной проверки возврата. Автоматического возврата нет.

Платёжная форма открывается в новой вкладке; на исходной странице доступна кнопка «Сменить способ оплаты». В Lava.top отправляются URL возврата: успех — на статус заказа, ошибка/отмена — на выбор методов. Вставить собственную кнопку внутрь чужой страницы нельзя. Возврат по URL никогда не подтверждает оплату: только авторизованный webhook с совпавшими суммой и валютой.

Создание защищено атомарным переходом состояния. При определённом отказе API (400/422/429) можно попробовать снова. При неоднозначной ошибке повторный запрос того же метода и валюты блокируется, но можно явно выбрать другой метод. Если процесс завершился в момент запроса, заказ остаётся в `creating` и требует проверки истории Lava.top. Имя и телефон для Bizum/Bancontact передаются в API, но не сохраняются в таблицах заказов.

Проверка после обновления: выбор валюты в боте, тариф и период, совместимые методы на сайте, возврат и смена метода, оплата старого счёта после смены, одна выдача услуги, дополнительная оплата в админке. Тесты API используют подмену ответов и не выполняют реальных платежей. Нужна проверка реальных способов на вашем аккаунте.

Локальные проверки: `python -m unittest discover -s tests -v`.
