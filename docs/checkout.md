# Страница оплаты

Новые заказы (тарифы и пакеты трафика) открывают `/pay/<случайный токен>` на `public_base_url`. Нужен публичный HTTPS-адрес панели. Сумма, скидка и параметры тарифа сохраняются до выбора метода. Значение `lava_payment_provider` для этих заказов не используется.

Поддерживаются все три валюты API Lava.top: RUB, USD, EUR. RUB: СБП, карта РФ (Smart Glocal или PAY2ME). USD: карта, PayPal, Apple Pay, PIX. EUR: те же методы плюс SEPA, iDEAL, Bizum, MB WAY, Bancontact. Матрица основана на схеме и примерах `https://gate.lava.top/docs/documentation.yaml` от 28.09.2026. Спецификация непоследовательна: enum указывает UNLIMINT, а некоторые примеры — UNLIMIT; код использует enum UNLIMINT. Некоторые региональные методы присутствуют только в примерах. Их фактическую доступность для аккаунта и ограничения суммы требуется проверять на Lava.top, она не гарантируется интерфейсом. CHECKOUT_PAGE закомментирован в документации и не используется.

Конвертация идёт по официальным курсам ЦБ (`https://www.cbr.ru/scripts/XML_daily.asp`), с учётом номинала валюты, без наценки. Сумма округляется до двух знаков через Decimal ROUND_HALF_UP. Курс кэшируется в процессе на час, документ старше семи дней не используется. Котировка заказа сохраняется в БД на 15 минут: POST принимает её токен, но не сумму из браузера. Просроченная котировка требует повторного подтверждения. При недоступном курсе исходная валюта остаётся рабочей. Нет автоматического увеличения цены до минимума провайдера: отказ Lava.top показывается клиенту.

Таблицы `checkouts`, `checkout_quotes`, `payment_attempts` создаются сервисом `vpnshop-init`. Ручная миграция не нужна. Заказы прежней версии, где invoice_id уже внешний, сохраняют свой канонический ID; при смене способа старый счёт регистрируется как попытка.

Смена валюты или метода создаёт новую попытку того же заказа. Ранее созданный счёт с теми же методом, валютой и суммой повторно используется. Старые ссылки не считаются отменёнными: API отмены разового счёта не документирован. Первый подтверждённый платёж ставит одну задачу выдачи по каноническому ID заказа; повторный webhook не дублирует задачу. Оплата другого счёта уже оплаченного заказа сохраняется как `extra_paid` и показывается в разделе «Система и логи» для ручной проверки возврата. Автоматического возврата нет.

Платёжная форма открывается в новой вкладке; на исходной странице доступна кнопка «Сменить способ оплаты». В Lava.top отправляются URL возврата: успех — на статус заказа, ошибка/отмена — на выбор методов. Вставить собственную кнопку внутрь чужой страницы нельзя. Возврат по URL никогда не подтверждает оплату: только авторизованный webhook с совпавшими суммой и валютой.

Создание защищено атомарным переходом состояния. При определённом отказе API (400/422/429) можно попробовать снова. При неоднозначной ошибке повторный запрос того же метода и валюты блокируется, но можно явно выбрать другой метод. Если процесс завершился в момент запроса, заказ остаётся в `creating` и требует проверки истории Lava.top. Имя и телефон для Bizum/Bancontact передаются в API, но не сохраняются в таблицах заказов.

Проверка после обновления: новый заказ, валюты и методы, возврат и смена метода, оплата старого счёта после смены, одна выдача услуги, дополнительная оплата в админке. Тесты API используют подмену ответов и не выполняют реальных платежей. Нужна проверка реальных способов на вашем аккаунте.

Локальные проверки: `python -m unittest discover -s tests -v`.
